El Problema de Negocio

¿Por qué quiebran los emprendimientos de comida?

El 80% de los negocios gastronómicos fija precios "al ojo" o con tablas manuales con errores contables graves.

Diagnóstico
01

Errores de Conversión

Los insumos se compran en bultos de 25 kg o galones, pero las recetas usan 250 gramos o mililitros. El cálculo manual del costo exacto por gramo genera desvíos de hasta un 35%.
Costia normaliza a unidades canónicas de compra vs. uso.
02

Ceguera del Costo Unitario

Una tanda de galletas rinde 12 unidades, pero el cocinero solo ve el gasto total del mercado. No sabe con certeza cuánto le cuesta elaborar una sola unidad.
Fórmula automática: Costo total ÷ Rendimiento de la tanda.
03

Margen vs. Markup

Creer que sumarle el 30% al costo es ganar el 30% del precio es el error contable más común. Si vendes a $1.300 lo que te costó $1.000, tu margen real es del 23%, perdiendo 7% de rentabilidad.
Costia implementa ambas fórmulas con selector transparente.

Arquitectura de Datos

El Motor de Datos: `datos.js`

Cómo se comunican las 5 páginas entre sí sin necesidad de un backend activo en esta primera etapa.

JSON & Web Storage

⚙️ Mecanismo de Sincronización

  • Capa de Acceso a Datos Centralizada: Ninguna página escribe directamente en el DOM ajeno; todas leen y escriben a través de `datos.js`.
  • Serialización con JSON:
    JSON.stringify(lista) para guardar en disco.
    JSON.parse(texto) para reconstruir los objetos en memoria.
  • Semilla Inicial Condicional: Si `localStorage.getItem("costia_insumos")` es nulo, inyecta la lista predeterminada automáticamente.
Garantiza persistencia permanente entre cambios de pestaña y recargas de página (F5).

💻 Código Representativo

// 1. Lectura segura con fallback de datos function obtenerInsumos() { let guardados = localStorage.getItem("costia_insumos"); if (!guardados) { guardarInsumos(INSUMOS_INICIALES); return INSUMOS_INICIALES; } return JSON.parse(guardados); } // 2. Escritura atómica en cliente function guardarInsumos(lista) { localStorage.setItem("costia_insumos", JSON.stringify(lista)); }

Módulo Central

La Calculadora de Recetas: `crear-producto.html`

El motor que transforma una lista de compras en una fórmula de producción con costos unitarios exactos.

Core Engine

🧮 Funcionamiento Interactivo

  • Adición Dinámica de Filas: Mediante document.createElement("tr") se insertan filas vinculadas a los insumos existentes.
  • Recálculo en Cascada: Cada cambio en un selector o cantidad dispara la función recalcularTodo().

Permite tanto crear nuevas recetas como editar recetas existentes reutilizando el mismo formulario inteligente.

Rigor Financiero

Lógica Matemática de Fijación de Precios

Dos metodologías claras para que el emprendedor elija cómo quiere rentabilizar su negocio.

Finanzas Gastronómicas
Método A

Margen Comercial (% sobre Venta)

Garantiza que del dinero total que paga el cliente, el porcentaje elegido sea ganancia neta. Es el estándar contable.

Precio = Costo Unitario / (1 - (Margen % / 100)) Ejemplo: Costo = $1.000 | Margen Deseado = 50% Precio = 1.000 / (1 - 0.50) = $2.000 Ganancia = $1.000 (el 50% exacto de la venta)
Método B

Multiplicador de Costo (Markup)

Muy utilizado en restaurantes y banquetes para cubrir gastos indirectos rápidamente (energía, gas, local).

Precio = Costo Unitario × Multiplicador Ejemplo: Costo = $1.000 | Multiplicador = × 2.5 Precio = 1.000 × 2.5 = $2.500 Ganancia Bruta = $1.500 sobre el costo

Preparación de Sustentación

Preguntas Clave del Docente

Argumentos técnicos sólidos para defender las decisiones de diseño de este avance.

Banco de Respuestas

❓ ¿Por qué LocalStorage?

Respuesta:
"Aplicamos desarrollo iterativo. Priorizamos validar la experiencia de usuario (UX) y el motor matemático en el cliente antes de acoplarlo con la capa de persistencia en MySQL, asegurando una arquitectura desacoplada y libre de fallas de red."

❓ ¿Por qué Vanilla JS?

Respuesta:
"Para demostrar dominio profundo de los fundamentos: manipulación nativa del DOM, captura de eventos asíncronos y programación orientada a objetos en ES6 sin la sobrecarga ni complejidad de compiladores de frameworks."

❓ ¿Cómo evitan errores?

Respuesta:
"A través de funciones centralizadas de normalización en `datos.js` y validación de relaciones en memoria, impidiendo que el usuario borre insumos que alimentan productos existentes."
